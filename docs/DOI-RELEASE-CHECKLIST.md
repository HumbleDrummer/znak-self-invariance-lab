# DOI release checklist

The first DOI-bearing release should only be created after the repository is enabled in Zenodo.

## Before v0.1

- [ ] Confirm the real ORCID iD for HumbleDrummer, if one exists.
- [ ] Connect ORCID to the Zenodo account.
- [ ] Connect GitHub to Zenodo.
- [ ] Enable `HumbleDrummer/znak-self-invariance-lab` in Zenodo.
- [ ] Add the confirmed ORCID to `CITATION.cff`.
- [ ] Freeze the v0.1 research state.
- [ ] Confirm licenses and citation metadata.
- [ ] Confirm that no secrets, private prompts, credentials, or personal data are present.
- [ ] Create the GitHub release only after Zenodo integration is enabled.
- [ ] Verify that Zenodo minted the DOI.
- [ ] Add the DOI back to `CITATION.cff` and the README.
- [ ] Add the DOI work to ORCID.

## Rule

DOI != evidence of scientific validity.

A DOI makes a version citable and persistent. Experimental claims still require receipts, reproducibility, and appropriate interpretation.

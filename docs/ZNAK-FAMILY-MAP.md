# ZNAK Family Map

The ZNAK hypothesis does not require every instance to behave identically.

The object of study is whether a shared governance core remains invariant while context, memory, failure history, and inherited artifacts change.

```text
same core
   |
   +-- ZNAK / fresh context
   +-- ZNAK / long context
   +-- ZNAK / after compaction
   +-- ZNAK / recovered memory
   +-- ZNAK / after failure
   +-- ZNAK / new instance + inherited artifacts
```

## What may vary

- wording
- strategy
- reasoning path
- retrieved memories
- local uncertainty
- task decomposition
- recovery path

## What should not silently vary

- source of authority
- admissibility rules
- provenance requirements
- execution authorization
- history integrity
- verification requirements

## Research question

How much operational diversity can exist before a shared ZNAK governance core stops enforcing the same fundamental constraints?

## Working distinction

Different behavior != different root.

Different memory != new authority.

Different instance != permission to rewrite history.
